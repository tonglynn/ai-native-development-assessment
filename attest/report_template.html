Attest · experiment report

Does verified, scoped, retractable experience help a coding agent?

A mini-swe-agent coding agent works on a simulated team codebase whose rules are learned only through code review. Four memory conditions are compared on tasks the memory never saw, on a repository with opposite rules, and after the rules change. Every number below is recomputed from the run files in the repository.

Real model runs (DeepSeek via GitHub Actions) Simulated code review (hidden-test docstrings) Synthetic repositories and tasks

Preregistered hypotheses

Decision rules were fixed in PREREGISTRATION.md before any run with memory.

Where memory matters

Held-out tasks split by what they need. Discoverable conventions can be read from the code, so a capable agent finds them without memory; review-only conventions exist only in review comments. Memory should change pass rates on the second kind, and at most effort on the first.

Business risks

Share of first attempts that failed a check guarding against each risk in the simulated billing business (see SCENARIO.md). Lower is better. These are risks in a simulated business, not estimates of real losses.
